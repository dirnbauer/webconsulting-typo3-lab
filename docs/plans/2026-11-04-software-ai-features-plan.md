### 1.2 How the Desiderio site is generated (the pattern to reuse)

- `desiderio:styleguide:seed` builds the whole site 505 from PHP data classes (`DES/Classes/Data/StyleguideShowcasePages.php` → `subpages()` lists every page in seeding and menu order; `Classes/Data/Showcase/*.php` hold the sections). Pages are found by parent + title or slug, moved when `formerSlugs` match, and `formerSlugs` become regex `sys_redirect` rows.
- `/features` and `/ai`: `ShowcaseFeaturePages::section(hub, categories, section, formerSection)` → one hub page (sales hero, one `desiderio_blogteasers` block per category with 3 columns, AI-only strategy block, CTA banner) plus one page per feature with the fixed outline **herosaas → contenthighlight (problem) → gallery (tour) → benefitcards (4 benefits, 2 columns) → faq → [codeblock install] → [contenthighlight thank-you] → ctabanner**. `ShowcaseFeaturePagesTest::testEveryFeaturePageFollowsTheSameOutline` pins that sequence and `testTheSplitKeepsThe27Features` pins `1+17` and `1+10` pages.
- Links in data are placeholders only: `{{page:<slug>}}`, `{{site:<id>[/<slug>]}}`, absolute `https://` or `t3://page?uid=`. A unit test forbids plain `/paths`.
- Screenshots are `ShowcaseBlocks::screenshot('<name>-<hash8>.webp', title, alt, description)`; `frontend-` prefix → `Resources/Public/Styleguide/Frontend/`, else `Backend/`. `ShowcaseFeaturePagesTest::testEveryScreenshotExists` requires the file and the name pattern `^((frontend-)?feature-[a-z0-9-]+|hero-[a-z]+)-[0-9a-f]{8}\.webp$`. Every shot must be **16:10** (the hero, the gallery and the hub cards crop to 16:10). `Build/Scripts/capture-feature-screenshots.mjs --base <url> --shots <json>` takes them (Playwright, 2× DSF, WebP q92, content-hashed names); `--relink` repoints a reference `<name>-XXXXXXXX.webp` at the newest file of that name.
- Hero photos of hubs: `ShowcaseHeroPhotos::for('<page>')` (AI-generated people, 1440×900 WebP in `Styleguide/Heroes/`).
- Menu: first-level pages in `subpages()` order (Product, Website tools `/features` with the lab-seeded `/templates` child, AI and agents `/ai`, Solutions `/target-groups`, Pricing, News and demos `/resources`; the site package adds `/downloads`). `MenuNamesTest`: nav titles ≤ 20 chars on level 1, ≤ 42 below, abstracts required, ≤ 160 chars. 3 menu levels with flyouts. The home page uses the same main menu (4.27.3).
- Page films (one per feature/hub page, 35–60 s, 1920×1080, burned-in captions): `WT/packages/site_package/Build/Film/` (`film.html` + `films/*.mjs` specs + `lib/timeline.mjs` + `generate-film-audio.mjs` + `render-films.mjs`) → `Resources/Private/Fixtures/Films/<id>/` (MP4, WebP poster, VTT, `film.json`, committed) → `sitepackage:films:seed` puts a `desiderio_featurevideo` + transcript `desiderio_accordion` right after the page's hero (found by slug). Scene builders available in `film.html`: `hook`, `title`, `shot`, `points`, `grid`, `montage`, `split`, `end`. Narration: fal.ai ElevenLabs voice "George" (speed 0.9, about 2.1–2.3 words/s), music beds via Eleven Music, `--check` runs Whisper, `--trim` cuts stray fragments.
- The home product film is separate: `DES/Build/Film/film.html` + `DES/Build/Scripts/render-film.mjs` + `generate-film-audio.mjs` → `Resources/Public/Styleguide/Video/desiderio-film-<hash>.mp4` referenced by `ShowcaseBlocks::productFilm()` (the script rewrites the hash). 89 s, 14 narration lines in `Build/Film/audio/narration.json`.
- Translations de/zh/hu: `sitepackage:content:translate --site=desiderio` with memories keyed by English text in `WT/packages/site_package/Resources/Private/Data/Translations/desiderio/{de,zh,hu}.json` (1.5–1.7 MB each). New English copy needs entries first (`--dry-run --missing=-` lists them). Append entries as text; never rewrite the JSON (it has a mis-indented line, a rewrite reformats thousands of lines).
- Copy rules: `docs/content/style-guide.md` and `canon.yaml` (`packages/site_package/Resources/Private/Data/Content/canon.yaml`): British English, sentence case, headline ≤ 60 chars/8 words (aim 45), eyebrow ≤ 24 chars, button ≤ 24 chars/3 words, sentence ≤ 25 words, no superlatives, numbers only from canon facts. `lint-copy.php` and `sitepackage:content:audit` check it.
- Seeding order and the full command list: `docs/content/seeding.md` (steps 1–14). After a styleguide reseed the Jev seed, the templates overview seed and the films seed must run again, then translate, then flush + Solr.

### 1.3 Traps that apply to this work (from memory, all still valid)

- Never `composer install/update` in DDEV while clones are linked without the `.lab-links` hook; lock-only bumps on the host with PHP 8.5: `/opt/homebrew/opt/php@8.5/bin/php $(which composer) update <pkg> --no-install --no-scripts`. The DDEV container has no GitLab SSH key (private Poppy and webcon-templates repos). After any Composer run: `ddev exec bash -c 'rm -rf /tmp/opcache/*'` + `ddev composer dump-autoload`, then check `grep -c autoload-include vendor/composer/autoload_static.php` = 1, `grep -c <ext_key> vendor/typo3/PackageArtifact.php` > 0, `/` and `/typo3/login` answer 200.
- Several sessions share MAIN. Commit only explicit paths, never `-a`. Before every push: `git log --oneline origin/main..HEAD` as its own command; push the verified SHA (`git push origin <sha>:main`); if a foreign commit appears, stop and tell the user.
- Mutagen: `ddev mutagen sync` before a container reads a host edit (translation memories, specs) and before `git status` after a container wrote files. `var/` is not synced into the container.
- A styleguide reseed deletes every Desiderio element on its pages (films included) and the Powermail Lab content → always follow it with `webcon-jev:examples:seed`, `webcon-templates:overview:seed`, `sitepackage:films:seed`, then translate.
- Never two seeders or translate runs at the same time; check `/proc/*/cmdline` in the container, not `ps`.
- Production is behind basic auth; data runs happen on the host with `sh var/prod-run.sh var/prod-<name>` (git-ignored run folders); the auto-mode classifier blocked agents from production writes before, so WP10 prepares the script and the user runs it when an agent is refused. Every push to `main` deploys and restarts production; no push while a prod run is going.
- Keep the last 3 prod versions; check `df -h /` and `free -m` on the host before deploying; batch deploys.
- No real contact data on Desiderio pages (demo identity rules); no real customer names of T3 Ops / Ledger / CapexOne (see 4.x "never claim" lists); no personal or financial data in screenshots.
- Workers run on Opus 5.5 only. Browser tests never click `mailto:`.
- The in-app browser pane renders ddev pages unstyled; visual checks use Playwright from `MAIN/packages/desiderio/node_modules`.
- (found in WP0) `ddev -p webconsulting-typo3-lab …` run from WT refuses ("project root is already set … refusing to change"): run `ddev` from MAIN (`cd MAIN && ddev …` in a subshell) or use `docker exec ddev-webconsulting-typo3-lab-web` / `docker exec ddev-webconsulting-typo3-lab-db mysql -udb -pdb db` directly. zsh here has no `timeout` binary.
- (found in WP0) The `typo3-local` MCP server of the editor can launch competing DDEV builds; a `ddev start` that fails with a container-name conflict is retried once before anything else is suspected.
- (found in the Ledger prep) The user's shell profile exports `REDMINE_URL` and `REDMINE_API_KEY`. Next.js and `node --env-file` keep already-set variables, so a dev server started from a normal shell inherits the real Redmine credentials. Unset both (`unset REDMINE_URL REDMINE_API_KEY`) before starting any demo app; the Ledger seed guard refuses otherwise.
- (found 2026-11-04 11:02, WP4b) **A content block field added in the linked Desiderio clone is live in the lab the moment the YAML is saved**: every page with that element answers 500 (`RecordPropertyNotFoundException: Record property "desiderio_featurevideo_variant" is not available`) until the schema update (`ddev exec vendor/bin/typo3 extension:setup`; this lab has no `database:updateschema` command, that one belongs to typo3_console) and `cache:flush` have run. Whoever edits a block's `config.yaml` runs both in the same minute, before any other check; WP4b ran them at about 11:04 for the `variant` field and the lab answered 200 again at 11:07. The same applies to TCA changes in `Classes/` and to new `ext_tables.sql` entries.

Each Claude session also spawns one `typo3 mcp:serve` PHP process in the web container through the `typo3-local` MCP server (350 MB each); they are harmless but explain the memory.
- (found by WP2.0) `tt_content` has 942 columns in this lab (every Content Blocks field of Desiderio, Grande and Astryx is a column). New block fields are cheap individually, but WP9 checks `SHOW TABLE STATUS LIKE 'tt_content'` and the row-size warning in the install tool's database analyzer before the release; prefer reusing existing fields (`variant`, `layout`) over new columns where the type fits.

### 4.11 Strategy review: what the five points do not yet say (planner's review, 2026-11-04; content only, no project work)

Measured against the technology of November 2026, the strategy covers agent tools, human approval, the registry, model choice and governance well, and names llms.txt, agents.md, schema.org data, x402, the EU AI Act, C2PA and EU hosting. It does not yet state the following as standards. Each item is written as the line the strategy section or the films can use, with the reason.

1. **"API first, agents second-class nowhere."** Every product ships a documented API, typed data, llms.txt and agents.md, Markdown for agents where a page is text, and typed browser tools (WebMCP) where a visitor journey matters. Reason: Rauch's "the third customer"; is-agentic.com scores sites on exactly this; the lab builds WebMCP into every upgrade already, but the strategy does not say so.
2. **"Accessible by default."** WCAG 2.2 AA for every product, automated scans plus mandatory human review, an accessibility statement per site. Reason: the European Accessibility Act applies since 28 June 2025; the lab's WCAG skill and the Desiderio contrast gates exist, the strategy is silent.
3. **"Secure from the supply chain down."** Dependency audits before and after every update, signed releases and an SBOM, MFA for every backend, a hardening checklist, and the Cyber Resilience Act's reporting duties (since 11 September 2026, full obligations from 11 December 2027) planned for. Reason: the strategy handles permissions and secrets, not the supply chain; T3 Ops and the skills do, so the strategy should claim it.
4. **"Proof, not promise."** Every change to a live site is proven with evidence before release: baseline, staging, before-and-after comparison at strict zero, a signed closure. Reason: this is the lab's strongest differentiator (the upgrade graph, T3 Ops evidence reports) and it applies to agent-made changes exactly as to human ones.
5. **"Operated, not only built."** Monitoring, verified backups, an incident process and update evidence belong to every product from day one. Reason: the strategy's trace store covers agent runs; the host outage of 2026-09-19 and the T3 Ops stack show that operations are part of the governance clients buy.
6. **"Fast and light."** Core Web Vitals in the green, static caching, modern image formats, EU hosting with a small footprint. Reason: performance is the one quality every visitor and every agent measures; the strategy mentions "fast, static pages" only on the GEO page.
7. **"Private by design."** Data minimisation, EU-based models without retention, no training on client data, AI output labelled, third-party embeds loaded only after a click. Reason: the AI Act transparency rules are in the strategy; the rest is practised (Ledger, MedAtlas, CapexOne Plus, the YouTube facade) but not stated.
8. **"Costs you can see."** Every AI task shows its cost and runs under a cap. Reason: already readiness question 5; promote it to a visible standard, because it is what makes fixed-price AI work possible.

What stays out on purpose: sustainability reporting and carbon accounting as a standard (no product measures it today; a line in item 6 covers the footprint), certifications (none exist; D11), and anything that would need implementation to be true today.
