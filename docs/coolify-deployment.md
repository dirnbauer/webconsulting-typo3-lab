# Coolify deployment and DDEV synchronization

The TYPO3 lab is deployed from `docker-compose.coolify.yml` to
`https://typo3-lab.webconsulting.at`. The Compose stack owns persistent
volumes for MariaDB, `public/fileadmin`, TYPO3 runtime data, the TYPO3
encryption key, and Solr data.

## Coolify settings

- Build strategy: Docker Compose
- Compose file: `/docker-compose.coolify.yml`
- Public service: `web`, port `80`
- Domain: `https://typo3-lab.webconsulting.at`
- Health check: `/healthz` (the image health check supplies Basic Auth)
- Basic Auth user: `lab`
- Basic Auth password: generated by Coolify as `SERVICE_PASSWORD_BASIC`

Database credentials are generated by Coolify through `SERVICE_USER_DB`,
`SERVICE_PASSWORD_DB`, and `SERVICE_PASSWORD_ROOT`. They are never committed.

## Synchronize data

Inspect both environments without changing data:

```bash
Build/Scripts/sync-coolify.sh status
```

Replace Coolify data with the local DDEV database and fileadmin:

```bash
Build/Scripts/sync-coolify.sh push --confirm
```

Replace local DDEV data with the Coolify database and fileadmin:

```bash
Build/Scripts/sync-coolify.sh pull --confirm
```

Both directions create a backup before replacing data. Coolify backups are
stored below `/var/backups/typo3-lab/` on the server. Pull operations create a
DDEV database snapshot and a fileadmin archive below
`.tarballs/coolify-sync/`.

The push operation also transfers the existing TYPO3 encryption key so
encrypted values in the imported database remain readable.
