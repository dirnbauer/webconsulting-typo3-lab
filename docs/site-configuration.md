## File Layout

Each site is a directory under `config/sites/<identifier>/`:

| File | Purpose |
|---|---|
| `config.yaml` | Base URL, `rootPageId`, languages, dependencies, error handling, route enhancers. |
| `settings.yaml` | Desiderio site settings (`desiderio.*` tokens). Keep tokens here, not duplicated in `config.yaml`. |

**Convention:** one source of truth for Desiderio tokens. If a site has
`settings.yaml`, do not repeat the same keys under `settings:` in `config.yaml`.

## Adding a Site

1. Create or import the page tree and mark the root page with `is_siteroot=1`.
2. Add `config/sites/<identifier>/config.yaml` with a unique `rootPageId` and a
   clean `base` URL (avoid `autogenerated-*` path prefixes).
3. Add `settings.yaml` when the site uses Desiderio presets.
4. Flush caches and verify with `site:list` and the smoke check in the root
   README.

TYPO3 auto-generates `config/sites/autogenerated-<uid>-<hash>/` stubs when it
finds a siteroot page without a matching site config. Delete those stubs once
the real configuration exists.

## Troubleshooting

### Duplicate root pages

**Symptom:** Admin → Site Management → Sites reports the same page ID in
multiple site configurations.

**Common causes:**

1. **Autogenerated stub** — a leftover `autogenerated-<uid>-<hash>` directory
   points at the same `rootPageId` as a hand-written config. Delete the stub
   directory; keep the real site config.
2. **Workspace move pointers** — staged moves of siteroot pages appear as extra
   siteroots at `pid=0` with UIDs in the 900+ range and `t3ver_wsid > 0`. These
   are not live pages. Discard the staged move in the workspace instead of
   deleting live records.

Check workspace versions:

```sql
SELECT uid, pid, t3ver_oid, t3ver_wsid, t3ver_state, sys_language_uid, title
FROM pages
WHERE is_siteroot = 1 AND deleted = 0
ORDER BY uid;
```

- Live translation overlays (`l10n_parent > 0`, `t3ver_wsid = 0`) are expected
  and do not need a separate site config.
- Workspace versions (`t3ver_wsid > 0`) need `RollbackWorkspace` (MCP) or
  discard in the backend Workspaces module — not a live `delete`.

### Unassigned site configurations

**Symptom:** "Website configurations that are not assigned to any page."

**Cause:** `rootPageId` in `config.yaml` points at a page that no longer exists
(not even soft-deleted).

**Fix:** Either restore the page tree or remove the orphaned
`config/sites/<identifier>/` directory.

Verify root pages:

```sql
SELECT uid, title FROM pages
WHERE uid IN (<rootPageId list from config/sites/*/config.yaml>)
  AND deleted = 0 AND is_siteroot = 1;
```

### Broken site config

A config without `rootPageId` and `base` (for example a leftover `main` stub with
only partial language entries) is invalid. Delete it unless you can assign a real
root page and default language (`languageId: 0`).

## MCP and Workspaces

The lab uses `hn/typo3-mcp-server` for agent-driven edits.

| Setting | Location | Effect |
|---|---|---|
| `localUnsafeMode` | Extension Configuration → `mcp_server` (Security) | `auto` (default): live writes on DDEV/Development; `off`: workspace-only writes. |
| `options.mcpServer.strictSandbox` | User TSconfig | Forces production-safe behaviour even on DDEV. |
| `workspace_id` | MCP tool parameter | `0` = live (local mode only); `1+` = staged in that workspace. |

**Deleting in a workspace** stages a delete placeholder; the live record stays
until the workspace is published. **RollbackWorkspace** discards staged changes
(moves, edits, deletes) against the live UID.

Call `GetCapabilities` at session start to confirm `allows_live_writes` for the
current environment.

## Verification Checklist

After any site config change:

```bash
ddev exec vendor/bin/typo3 lint:yaml config/sites
ddev exec vendor/bin/typo3 site:list
ddev exec vendor/bin/typo3 cache:flush
```

Frontend smoke check (from repository root):

```bash
for url in / /14/ /blog/ /typo3-blog/ /desiderio-corporate-starter/ /typo3-vienna-camp-2026/ /mtug-camp-munich-2026/; do
  ddev exec curl -k -s -o /dev/null -w "$url %{http_code}\n" "https://webconsulting-typo3-lab.ddev.site$url"
done
```

In the backend, open **Admin Tools → Settings → Configuration →
[site]configuration** and confirm:

- no duplicate root pages
- no unassigned configurations
- site count matches the table above
